Embed VKF in a static webpage

Use the page-wide selector, then download vektor-flow-browser-wasm.zip from the download page. Package availability varies by release; the selector and download page show it. You can also build the same package from source. It is not a vkf --wasm CLI export flag.

Build the bundle

After building the browser compiler as described in the setup guide, install the repository JavaScript dependencies and package it:

npm ci
node tools/package-browser-compiler.mjs --output=dist/browser-vkf

The output contains vkf-shared-compiler.mjs and an artifacts/ directory. Keep them together beside the webpage that imports the compiler module. Packaging source.

Connect it to your page

This minimal host runs the same VKF compiler as the desktop tools, compiled to WebAssembly and executing entirely client-side. The HTML and CSS remain yours.

<textarea id="vkf-source">double(value:int) -> int: value * 2
:: double([1, 2, 3])</textarea>
<button id="run-vkf">Run VKF</button>
<pre id="vkf-output"></pre>

<script type="module">
  import { loadSharedCompiler } from "./vkf-shared-compiler.mjs";

  const compiler = await loadSharedCompiler();
  const source = document.querySelector("#vkf-source");
  const run = document.querySelector("#run-vkf");
  const output = document.querySelector("#vkf-output");
  run.addEventListener("click", () => {
    try {
      const result = compiler.run(source.value);
      output.textContent = result.kind === "console"
        ? result.stdout
        : "Program emitted UI output.";
    } catch (error) {
      output.textContent = String(error);
    }
  });
</script>

The JavaScript host may update its own page, but VKF user code receives no network, server, filesystem, process, DOM, localhost, or host API access. Unsupported source fails clearly. The WASM module has no host imports.

This small example runs synchronously. For an editor accepting arbitrary user input, use a disposable Web Worker with a bounded timeout, as the site runner does, so a long calculation cannot block the interface. The site allows 15 seconds so cold WASM execution also works on slower mobile devices. Visual results are compiler-owned retained-scene arenas; mount them through the VKF UI runtime as the site runner does. That handoff creates real <vkf-viewport>, <vkf-window>, and <vkf-panel> HTML elements, so a host can embed and style the returned surface directly. A Viewport is the root, a Window includes its title bar and window controls, and a Panel is borderless and handleless. Their pos, width, and height are relative to the parent Viewport.

Serve the files

Use a static HTTP server locally and HTTPS when publishing. Preserve module and artifact paths; serve .wasm as application/wasm and .mjs as JavaScript. No application backend is required. Opening a file:// URL is not the supported hosting path.
