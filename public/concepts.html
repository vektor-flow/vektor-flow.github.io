Guide / What

VKF combines a keyword-free, scope-based core with vector operations, mathematical libraries and graphics. Start with the model below; follow a link for exact rules, further examples or implementation details.

Values, scopes and convenient syntax

VKF is value-oriented and makes change explicit. Declarations and updates are different operations; aggregate updates preserve alias identity, so VKF is not a purely functional language. Operators, types, functions and scopes form the core.

Bindings · types and containers · control flow and errors · pipes and ranges · scope and modules.

Functions, vectors and indices

Functions can apply through vector layers. Attached suffixes identify ordered dimensions: shared indices align elementwise and unmatched indices broadcast. Index names otherwise carry no meaning. Plotting is the exception: its topology and time indices control how values connect or animate.

Execution and measured performance


Lazy data access and parallel work when beneficial are design goals. The native optimiser searches legal execution policies within a budget and checks results. Those choices can trade compilation time for faster execution; they are not universal speed guarantees.


Execution-policy search and limits → version-matched native and browser measurements → benchmark methodology.


Native measurements do not establish browser performance or results for another compiler version.


Quantum computes; .concurrent coordinates


Quantum owns numerical execution decisions. A reduction, vector calculation or simulation can be fused, vectorized or scheduled by the compiler without adding threads, task handles or GPU-launch syntax to the program.


.concurrent is the separate native event/I/O library. Its queue() is a blocking, destructive FIFO; broadcast() gives every active subscriber a queue-like branch; process(...) starts an isolated VKF function and returns a handle with join() and kill(); and shared(value) preserves ordinary value structure with immutable published generations. It deliberately has no mutable shared-pointer API, and its later publish/rebind surface remains unresolved.
