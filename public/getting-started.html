Build an interface


Use HTML and CSS for layout and styling, with VKF supplying calculations and behaviour. For a static webpage, the browser embedding walkthrough covers the bundle and host glue.


The compiled HTML/CSS application runtime is currently a Windows native capability; it is not the same as embedding the browser subset. Inspect the VKF program, HTML and CSS together.

For a website, build the browser runtime, embed it, and follow the static-hosting requirements.


The browser build recipe is not a general vkf --wasm export command. Its supported path and limitations are documented in the linked walkthrough.


Coordinate events, not numerical kernels


The examples above are ordinary calculations: Quantum decides whether their numeric work can be fused, vectorized or run in parallel. When a native program instead needs to coordinate I/O or independent event loops, import .concurrent. Use a destructive queue() for work distribution and broadcast() when every active listener needs each later update. A process(...) runs an ordinary VKF worker, while shared(value) keeps one immutable published value available without making it a mutable shared pointer.


Start with the native event pipeline or fan-out, then read the concurrency contract. The browser compiler currently diagnoses reachable .concurrent operations until its isolated-worker runtime exists.
