Vektor Flow

Mathematics → programs → interactive views

Keep the mathematics.
Explore what it does.

Vektor Flow is an experimental programming language for people who build mathematical models, scientific tools and visual explanations. Work with symbolic expressions and matrices, then bring the results into interactive plots in the browser.

Use one mathematical description to connect a calculation, its derivative and its picture. Inspect the relationships as you change the model, instead of maintaining separate formulas for every view.

A model you can investigate

Design a move. See where it overshoots.

How should a camera move between two positions? Use normalized time and position from 0 to 1. Choose the endpoint slopes, solve for a cubic path, and differentiate it symbolically. Compare position with velocity, then look at the same motion as a position–velocity curve.

01 · Solve a matrixFour constraints → four coefficients

Start at 0, end at 1; choose the slope at each end.

02 · Keep the expressionPath → derivative function

Inspect the formula behind the motion and its rate of change.

03 · Plot both viewsTime curves + phase portrait

Look for overshoot and reversal before using the path.

Locally browser-tested · publication pending. This local example uses APIs present in the published 0.7.2 package. The combined program was locally checked with endpoint slopes 0 and −2, including rerun and phone layouts. Output and plots appear only after execution; no result is prefilled.

Try it: run the program, then change exit_slope from 0 to -2 and run again. With zero endpoint slopes, the mathematical solution is [0, 0, 3, -2], giving 3x² − 2x³. A negative final slope asks the path to reverse before it arrives: look for the overshoot in position and the sign change in velocity.

Locally tested example · Loading compiler…
la:.linalg
exit_slope:0
c:la.solve([[1,0,0,0],[1,1,1,1],
            [0,1,0,0],[0,1,2,3]], [0,1,0,exit_slope])
path(t,a,b,d,e):a+b*t+d*t^2+e*t^3
slope:deriv_t(path)
::c
::path(0.5,c.0,c.1,c.2,c.3)
::slope(0.5,c.0,c.1,c.2,c.3)
t:0.005*[0..200]
curves:.ui.viewport
curves.add(x:t_u,y:path(t_u,c.0,c.1,c.2,c.3),color:[0.25,0.72,1,1])
curves.add(x:t_u,y:slope(t_u,c.0,c.1,c.2,c.3),color:[1,0.45,0.18,1])
curves.show()
phase:.ui.viewport
phase.add(x:path(t_u,c.0,c.1,c.2,c.3),y:slope(t_u,c.0,c.1,c.2,c.3),color:[0.3,0.9,0.55,1])
phase.show()

The matrix rows encode p(0), p(1), p′(0) and p′(1). The compiler’s deriv_t function transform differentiates the cubic in VKF. Both plots sample the path and its derived function using the actual solved coefficients passed explicitly as parameters. This working 0.7.2 example uses function differentiation rather than first-class symbolic domain expressions. These are sampled curves, not a claim of adaptive symbolic plotting or a physical simulation.






A mathematical workspace, still taking shape


VKF connects symbolic computation, ordinary functions and dimension-aware data with visual programs. A Window is a class-like function for a UI container; a Viewport is a screen or an embedded VKF region for presenting a view.


The published engine is the 0.7.2 experimental preview. The previously verified examples below cover a limited set of behavior; they do not establish complete language support. Browser execution and target support vary; the combined motion example above still needs browser verification. See capabilities and implementation status and work in progress.

Loop indices


$ is the current value, $i the named coordinate, and $0 the outermost loop's iteration index. Nested loops use $1, $2 and later depths.


Editable example · Loading compiler…

    ::$i
    ::$0
    ::$
Console

0

1
1
20



Scalar scopes do not add a loop. Loop indices are read-only and scoped to their loop.

Anonymous and named dimensions


Names align by identity. Anonymous dimensions align positionally with other anonymous dimensions. A suffix names the complete rank; ... explicitly preserves the remaining anonymous dimensions.


Editable example · Loading compiler…
A:[[1,2],[3,4]]_ij
::A
B:[[[1,2],[3,4]],[[5,6],[7,8]]]_i...k
::B
Console
[[1, 2], [3, 4]]
[[[1, 2], [3, 4]], [[5, 6], [7, 8]]]



A repeated dimension in an access selects a diagonal. A reduction removes only the dimensions explicitly selected. Mismatched aligned sizes are errors.

Templates


Double quotes interpolate immediately. Single quotes defer interpolation until .format(...). A prefix : spills runtime arguments.


Editable example · Loading compiler…

::"x = $x.1f"

::'[$x.1f, $y.1f]'.format(:s)
Console

Binding function arguments


Declare ordinary parameters in parentheses. Square brackets bind named arguments into a callable; parentheses evaluate the remaining arguments.


Editable example · Loading compiler…
power(x,n):x^n
cube:power[n:3]
::cube(2)
Console
8



Ordinary names such as x_min and particle_count remain identifiers; alphabetic suffixes select structural dimensions where applicable.


Geometry and physics


Properties describe meaning; dimensions describe structure. Connected dimensions u, v, w describe curves, surfaces and volumes. c describes components; t describes time. Other letters group values without naming an object category.


Connected geometry


One add call creates one layer. Three coordinate components make this a 3D curve:


Editable example · Loading compiler…
frame:.ui.viewport
p:[[0,0,0],[1,1,2],[2,0,1]]_uc
frame.add(p:p)
frame.push()
frame.show()
Console


set changes defaults, add creates a layer, push freezes the composed state, append adds and pushes, and plot appends and shows.


Explicit topology


References connect independent groups. The m dimension holds member slots.


Editable example · Loading compiler…
frame:.ui.viewport
p:[[0,0,0],[1,0,1],[1,1,2],[0,1,3]]_ic
frame.add(p:p,edge:[[0,2],[2,3]]_bm)
frame.push()
frame.show()
Console


Here i groups vertices and b groups edges; reference values connect them. The group letters themselves have no built-in vertex or edge meaning.


Unit-aware state evolution


A Law is an ordinary function over physical state. For constant acceleration:


Editable example · Loading compiler…
: .units
advance(p,v,a,dt):(
    p:p+v*dt+a*dt^2/2,
    v:v+a*dt
)
state:advance(0m,2m/1s,1m/1s^2,2s)
::state.p
::state.v.to(m/s)
Console
6 m
4 m/s



The same semantics should support compiler-selected CPU or GPU execution without user-written kernels or memory transfers.


Motion fields


One ordinary function advances positions across entity and component dimensions:


Editable example · Loading compiler…
:.physics.units
advance(p,v,dt):(p:p+v*dt,v:v)
p_ic:[[0,0,0],[1,0,0]]m
v_ic:[[0,1,0],[0,2,0]]m/1s
state:advance_ic(p,v,2s)
::state.p
::state.v.to(m/s)
Console
[[0, 2, 0], [1, 4, 0]] m
[[0, 1, 0], [0, 2, 0]] m/s



World integration is incomplete. Its design treats motion without _t as initial state and motion with _t as prescribed state. Prescribed position takes precedence over velocity, then acceleration, then Laws.

Event and I/O concurrency


Compute scheduling belongs to the compiler. Event and I/O concurrency uses ordinary functions with queues, broadcasts, processes and shared values.


Queue and process


Editable example · Loading compiler…
concurrent:.concurrent
worker(events):events.get()
events:concurrent.queue()
p:concurrent.process(worker,events)
events.put(42)
::p.join()
Console
42



A queue delivers each item to one consumer; get() waits efficiently.


Broadcast and shared values


Editable example · Loading compiler…
concurrent:.concurrent
updates:concurrent.broadcast()
ui_updates:updates.subscribe()
log_updates:updates.subscribe()
updates.put("ready")
::ui_updates.get()

Both active subscribers receive ready. shared accepts one ordinary value; published generations are immutable. Its update API remains a separate design decision.
