Begin with a program you can inspect.

Open a complete workflow or a small syntax example. You can inspect, edit and copy the source. Browser execution is disabled before release; the latest compiler is required before Run is enabled.

Changing the source clears the historical result. The notes below describe the intended execution paths; they do not qualify the unreleased compiler.

This review site offers editable examples, without compiler packages or a native SDK.

Use the command line for a native workflow.

A compatible native compiler supplies the vkf command. This review site does not offer a native compiler package.

vkf -v
vkf -e ':: 2 + 2'
vkf model.vkf
vkf -b model.vkf -o model
./model
CommandPurpose
vkf model.vkfBuild when needed and execute the program
vkf -b model.vkf -o modelBuild an executable without running it
vkf -e ':: 2 + 2'Evaluate source supplied as an argument
vkf -t tests.vkfRun discovered tests in a source file
vkf -t testsRun tests from a directory
vkf -vInspect the compiler version

These command forms come from the source driver. Native target support requires its own package and qualification; none is offered by this preview. The table does not promise cross-compilation.

Keep a relationship you can check.

A model has useful invariants before it has a large dataset. This small assertion program checks the endpoints and midpoint of a smooth path. Inspect the expected values or edit them for a future test run.

Run uses the current browser compiler. Edit, Run and Copy use the same source.

Editable example
p(t): 3 t ^ 2 - 2 t ^ 3

(p(0) = 0) ?! "start"
(p(1) = 1) ?! "end"
(p(0.5) = 0.5) ?! "midpoint"

Compile source in a WebAssembly worker.
The current runner loads the compiler module, WASM and data selected by the site manifest. It compiles editable VKF source and returns text plus retained-scene packets. Retained visual programs use the existing window dispatcher and shared renderer.
Read the complete client integration, including cancellation, error handling and disposal. Keep the compiler and runtime assets from the same site revision.


Embed a program in your page.
The shared Embedding guide contains one complete HTML/JavaScript client for the current compiler, a dedicated interactive viewport and a separate text console. Change the source and target elements to reuse it with any example.
The panel-area form shows how an HTML input changes the same editable VKF source used by Run.


Serve the complete bundle together.
The following notes describe how the embedded runtime is hosted. A compatible integration needs matching runtime files, relative paths and third-party notices; public hosting needs HTTPS.
python3 -m http.server 8000
Shared-memory execution needs browser isolation. A host can send Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp. The included isolation helper can establish the required policy through a service worker on compatible hosts and may reload the page once.
Keep the worker, WASM and data files under the same origin unless the host is deliberately configured for cross-origin isolation. 


Reuse the viewport controls.
The Embedding guide’s viewport supplies Box, Crosshair and Open axes, with None, Lines and Dots grids. Its lifecycle notes explain scoped frame identities and presentation APIs.
