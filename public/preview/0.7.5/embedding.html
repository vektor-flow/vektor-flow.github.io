HOW / EMBEDDING

Run VKF inside your page

Your page supplies the source and owns the run. The compiler returns text and scene packets; the shared renderer presents the scene.

Start with a real program from Examples. This guide explains the integration once. The HTML and JavaScript below are reference steps for a host application; they do not start another playground on this page.

1. Keep the runtime together

The current website uses inline-runner.mjs, its compiler worker and the package selected by current-compiler-release.json. Keep their relative directory structure, matching module/WASM/data files, renderer modules and native scene-label resources together. These examples describe the existing website modules; a standalone embedding SDK download is not offered by this review site.

Serve modules and assets over HTTPS, or localhost during development. The browser compiler needs isolated shared memory: Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp. Prefer those server headers. The site's isolation helper can instead install vkf-coep-sw.js under the same path and reload once after an explicit Run. That reload requires restoring the edited source and resuming only the user's requested run.

If the host sets a Content Security Policy, allow these same-origin module/classic scripts, module workers and service worker, compiler/scene resource fetches, styles and fonts, and WebAssembly compilation. A restrictive script-src needs 'wasm-unsafe-eval' for WebAssembly. Cross-origin resources must also satisfy COEP and their fetch CORS requirements. Keep the integration's relative URLs and the host's policy consistent.

2. Give source, viewport and console separate elements

The host's editable source is input. Put the interactive plot in its own viewport and execution text in a different console. Explain the calculation above those elements and stack them at full width, as the maintained examples do. These target elements illustrate the connection:

In the JavaScript steps, source, viewport, consoleOutput and status refer to these elements. The host attaches its own Run/edit/removal handlers once. It owns controller (the active run's AbortController), scene (the current mount), a source revision counter and the listener AbortController events. The steps share that state; they are excerpts, rather than a complete event-handling client.

3. Select the matching compiler once

Create one runner for this host owner, using the enabled manifest's exact files and source binding. Creation does not execute the program. runner.run prepares the package and worker when the user requests execution; reuse that runner for later runs. The modules below live beside this guide.

import {createInlineRunner} from './inline-runner.mjs';
import {ensureInlineRenderer} from './inline-renderer-loader.mjs';
import {mountRetainedSceneResult} from './inline-retained-scene-view.mjs';

const response = await fetch(new URL('./current-compiler-release.json',
  import.meta.url), {cache: 'no-store'});
if (!response.ok) throw new Error('Compiler manifest unavailable');
const release = await response.json();
if (![release.current_distribution, release.site_review_iteration]
    .some(policy => policy?.enabled && policy.runEnabled)) {
  throw new Error('Browser execution is unavailable');
}
const runner = createInlineRunner({
  moduleURL: release.package.module,
  wasmUrl: release.package.wasm,
  dataURL: release.package.data,
  expectedSourceBinding: release.browser_binding ?? release.compiler_source,
  timeoutMs: 360000,
});

VKF source stays a string: source.value. Copy a complete program from the spectral analysis example or another maintained example. JavaScript uses explicit operators such as a * b; VKF source uses its own range, index and implicit multiplication syntax. Do not translate VKF arithmetic into host JavaScript.

4. Execute, then present the real result

On Run, capture the source revision, create the active AbortController and disable repeated clicks. Dispose the previous scene before replacing it. Pass the source to the runner, put stdout/stderr in the console with textContent and hand retained packets to the shared renderer:

// In the host's async Run handler, after clearing the previous mount:
const result = await runner.run(source.value, {signal: controller.signal});
consoleOutput.textContent = result.output.stdout + (result.output.stderr ?? '');

if (result.packets?.length) {
  await ensureInlineRenderer();
  const mounted = mountRetainedSceneResult(viewport, result.packets);
  scene = mounted; // Keep the cleanup function for edit, rerun and removal.
  const presented = await mounted.presented;
  // null means this mount was removed before its first presentation.
  if (presented !== null) status.textContent = 'Completed.';
} else {
  status.textContent = 'Completed.';
}

After each await, the complete handler must check that its captured revision still matches and the host has not closed before changing output or installing a scene. An edit can arrive during compiler or renderer initialization. A cancelled or stale run must never overwrite the new source's result.

mountRetainedSceneResult supplies normal plot interaction and the native LaTeX scene text route, including ticks and coordinates. Its returned function removes the mounted scene; .presented resolves after its real first presentation or rejects on a rendering failure. Reuse that renderer rather than reconstructing plots, labels or physics in JavaScript. Plot style and axis visibility belong in the VKF program; the host does not add Axes/Grid selectors or duplicate plot navigation.

5. Handle errors, reruns and removal

Catch runner and presentation errors in the host's Run handler and report the actual error message in the console. Clear a failed scene. Later renderer failures arrive as vf-example-render-error on the viewport; its event.detail.message belongs in the same error path. Restore the Run button in finally, unless the host has closed, so an error can be corrected and rerun. Keep only one active run for an owner.

// On an edit: invalidate the pending result, cancel work and clear output.
revision++;
controller?.abort();
scene?.();
scene = undefined;
consoleOutput.textContent = '';

// On removal: also detach the host's listeners and await worker shutdown.
events.abort(); // events is the AbortController used for those listeners.
await runner.dispose();

The two cleanup groups above belong to different handlers. An edit cancels the active run and disposes its scene, while leaving the runner available. Removing the host also aborts its registered listeners and awaits runner.dispose(). Do not start a replacement owner while the old one is still closing. If page navigation disposes the owner, a return from the browser's back/forward cache must recreate it before another Run.

For the full website event handling, inspect current-documentation-examples.mjs and example-presentation.mjs. They connect the same runner and mount APIs to the shared editable examples. The panel-area form shows a host input that changes the VKF source. Keep one entry point per page: loading the same event-handling module through different query URLs creates separate owners.
