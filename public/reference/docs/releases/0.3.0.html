Version 0.4.7

VKF 0.3.0 — Native Scientific Stack

VKF 0.3.0 ships linalg, physics, dimensioned SI units, and symbolic as fully native standard libraries on Windows x64, Linux x64, and macOS ARM64. The release adds no Python, C++, assembler, or external linker dependency to installed VKF programs. The native visual ui system remains excluded.

Scientific libraries

  • linalg operates on ordinary rectangular nested vectors. It covers dot, cross, outer products, matrix multiplication, transpose, determinant, rank, inverse, solve, least-squares, solution spaces, RREF, null spaces, LU, QR, Cholesky, SVD, and eigen decomposition.
  • physics consumes linalg and owns rigid dynamics, collision/contact behavior, materials, and deterministic stepping.
  • physics.units and physics.units.si provide dimension-checked quantities, coherent derived units, and SI prefixes.
  • symbolic owns expressions, symbols, constants, relations, propositions, domains, constraints, exact manipulation, equations, ODE/PDE and recurrence solving, transforms, and compilation of resolved expressions to numeric functions.

Native lowering

The Windows x64 factorization path now updates four LU rows per pivot with a shared AVX2/FMA tile instead of reloading the pivot row for every target. Cholesky prefix dot products use four-lane AVX2 reductions. This follows the same locality principle as LAPACK's blocked Level-3 update design while retaining VKF's compact fixed 96×96 specialization. The embedded kernel is regenerated reproducibly from vkf_linalg_factor_x64.cpp by scripts/generate-native-linalg-factor.ps1.

Primary algorithm references:

  • LAPACK DGETRF
  • LAPACK DPOTRF
  • LAPACK DGETRF2

Verification

The release suite verifies the complete core and standard library through native vkf -t, then runs eleven scientific fixtures through native execution and standalone WASM ten times each with identical output required.

The linear-algebra laboratory compares seven operations with Eigen 5.0.0, faer 0.24.4, and SciPy 1.16.3. Every sample must satisfy reconstruction, residual, solution-error, and/or orthogonality limits before its time is accepted. The Windows x64 release gate uses 100 rotating same-host samples per implementation and requires every VKF/competitor mean ratio to be strictly below 1.5×. The completed release run passed all 21 comparisons; its worst ratio was 1.228× for Cholesky versus faer. Blocked LU measured 1.149× versus faer, 0.900× versus SciPy, and 0.579× versus Eigen.

The core spectral norm, Fannkuch, and N-body comparison remains independently gated below 1.5× C, Rust, and Zig on its controlled Linux x64 runner. Every documented program is compiled and executed ten times on every release target; exit code, stdout, and stderr must remain byte-identical.

The completed large-kernel core run used 1,000 raw samples per language and passed all nine runtime ratios; the worst was 1.489× for N-body versus Rust. Its x64 lowering packs independent distance chains, hoists shared body coordinates, retains a shared body's velocity across paired interactions, and packs both bodies' mass factors without changing source-order arithmetic. The four-kernel symbolic comparison also passed all 12 ratios against SymEngine, SymPy, and Symbolics.jl under the same strict 1.5× gate; its worst measured ratio was 0.233×.

The rebuilt Windows compiler passed 429 core tests, 442 native standard-library tests, 332 JavaScript/tooling tests, 11 native/WASM conformance fixtures with 10 identical executions per target, and all 67 documented programs with ten fresh compiles and ten fresh-process executions each.

Tooling

Prism and TextMate grammars recognize linalg, physics, symbolic, and the type builtin. Release automation now builds the three pinned linalg competitors and rejects the release if any validated ratio reaches 1.5×. Portable Windows, Linux, and macOS packages now include linalg.vkf explicitly. Aliased native modules are linked dependency-first so nested calls retain the callee's complete default-argument metadata; a .symbolic → .linalg regression test protects this packaging path.

Symbolic constant inspection now preserves owned expression storage across allocator implementations. SysV x64 register allocation also treats incoming parameters as live from function entry, preventing a preceding native call from clobbering vector components before their first explicit read. Release automation completes compiler, standard-library, parity, and package verification on all three targets before any comparative benchmark starts. The macOS ARM64 backend now preserves an owned temporary vector's allocation base while loading an indexed element, so cleanup always receives the original allocation rather than an interior element address.
