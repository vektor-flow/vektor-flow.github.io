Vektor Flow 0.4.5

Function-specific native optimization

The x64 native compiler can train the complete 256-policy landscape separately for each eligible canonical function. Each candidate is emitted as a one-function-at-a-time perturbation of the complete executable program and is checked against the baseline program's exact output. The combined ordered winner map must also preserve exact output before any function proof is retained.

The winning policy is retained under an identity derived from the canonical function body and argument/result signature, its transitively called canonical functions, string and output semantics, target, host, toolchain, proof scope, and baseline policy. A changed function or signature invalidates that function and its callers; an unrelated caller does not invalidate an unchanged callee.

The function proofs are reusable search inputs, not proof that an arbitrary mixture is safe. A separate program-composition receipt binds the full canonical program, the ordered winner map, target, host, toolchain, proof oracle, and baseline. It is stored only after the combined executable preserves exact output. An all-function-hit compile with no matching composition receipt runs the combined exact check before emission; only a matching composition receipt permits a zero-run cache hit.

Functions may use different proven policies in one artifact. Cache hits reconstruct the same ordered function-policy map and machine-code fingerprint without executing the optimizer. Missing proofs remain bounded to the baseline and one guided candidate per function; exhaustive search occurs only when it is explicitly requested.

Explicit exhaustive training is incremental. Complete 256-mask landscapes are retained in a namespace separate from bounded guided proofs. A repeated tune request reuses unchanged complete landscapes, searches only new or invalidated functions, and reports function_landscape_search_count and function_landscape_reused_count. A bounded auto result can never suppress a later exhaustive search.

Function-local landscapes are ABI-neutral. The borrowed-aggregate-parameter and direct-aggregate-result bits describe call-edge contracts, so the 256 reported masks alias those two bits to the corresponding ABI-neutral emitted artifact. They are never retained as independent function-local selections.

If an emitted function-local mask fails exact parity, that emitted artifact is never retained or timed as correct. Its receipt sets normalized_to_baseline, records the original rejected_code_hash, and times the exact baseline alias while reporting the normalized count. This normalization does not apply to the existing whole-module landscape.

The composed path admits deterministic, effect-free numeric programs with one scalar output, including parameterized and calling functions and owned local working data. For statically fallible operations, the concrete zero-input baseline must complete successfully; any candidate error or partial result fails exact parity, and an actually failing baseline retains no proof. Nondeterministic or externally effectful programs remain on the existing fail-closed path.

Native language comparison

The release benchmark runs spectral norm, fannkuch-redux, and n-body together as one native VKF, C++, Rust, and Zig program on one pinned Linux x64 host. A deterministic checksum preserves exact cross-language validation while the harness also retains the individual kernel sources and validation. The final report records 100 raw-kernel runs pinned to one logical CPU, plus separate fresh-process and compile samples. Exact numeric parity is mandatory.

VKF's one-time per-function landscape-training cost is reported separately. The ordinary VKF compile table measures fresh compiler processes that reuse the retained winners with zero optimizer runs. The report also states VKF-to-peer raw-runtime ratios explicitly so values below 1× and above 1× cannot be misread.

Adaptive masks select lowering only; they contain no parallel bit. Parallel eligibility, selection, and thread create/join/close counts are reported as a separate proof-gated execution decision.

VKF remains unsupported experimental software with unstable APIs and syntax.

Correctness, exact candidate and composition proofs, cache identity, native/WASM parity, package closure, and publication gates remain mandatory.

The browser release gate measures the direct MachineIR-to-WASM artifact on one macos-15 host across Chrome/V8, Firefox/SpiderMonkey, and Safari/JavaScriptCore. It uses ten warmups followed by 100 interleaved measured samples in every browser and for the same-host native VKF baseline. Each browser's warm-kernel mean must be strictly below 3x native; exactly 3x fails. The workflow additionally rejects missing browsers, mismatched frozen artifacts, source-identity drift, or inexact output.
