Vektor Flow 0.4.7

Language and compiler

Value-carried indices survive scalar arithmetic and lifted mathematical functions. For example, combining a radius vector indexed by _i with an angle vector indexed by _u produces coordinates indexed by _iu; passing those values to viewport.add keeps _i as the grouping axis and _u as the connected-curve axis. The browser renderer draws each _i group as a separate continuous curve instead of stopping at the first group boundary.

General native optimization

The native compiler applies general, correctness-checked transformations: scalar value reuse, dependency scheduling, loop-invariant reduction caching, independent-row SIMD, and target-specific register allocation on x64 and ARM64. Optimizer receipts are bound to exact compiler, IR, target, toolchain, and proof identities.

Resolved bundled linear-algebra operations may select verified native kernels without changing user-defined overrides. LU and Cholesky paths avoid redundant frame and input copies while preserving the public numerical, ownership, and fallback contracts.

Structural suffix syntax

Attached suffixes express ordered tensor dimensions directly: value_a is rank one and value_aq is rank two. Ordinary underscore identifiers take precedence when they resolve exactly.

Functions can capture compile-time call suffixes. Fixed dig, bit, and chr parameters and a final variadic character parameter support forms such as L[row:dig, column:dig](x:int) called with L_03(4), and _suffix[...args:chr](x:int) called with _suffix_abc(7).

Multidimensional indexing composes fixed and computed indices with : to preserve one dimension, ... to preserve the remaining dimensions, and :: to insert a size-one dimension. Bases and computed indices are evaluated once, and value.(:coordinates) spreads index coordinates.

The browser and VS Code highlighters recognize attached dimensions, compile-time suffix declarations, anonymous dimensions, and the dig kind.

Axis-aware statistics and analysis

Statistical reductions and analytical functions use structural suffixes to select their compile-time axes: stat.sum_j(values_ij), stat.mean_i(values_ij), symbolic.deriv_x(value), and symbolic.integ_x(value) all retain the remaining dimension structure.

Bounds and steps are governed by the selected suffix axis: q_from, q_to, and q_step for _q; integration uses dq for its constant measure. Without a coordinate vector, a sum step is an integer index stride. Supplying q: makes the same step coordinate-space; values are linearly interpolated onto its lattice before summation. The public stat.sum_q surface handles both sampled vectors and symbolic expressions. Reversed integral limits negate the result; a sum with bounds incompatible with its step is the empty sum (0).

Numerical interpolation uses the same compile-time selector independently of whether coordinates are supplied: stat.interp_i(values_i, i_to) uses indices, and stat.interp_i(values_i, i, i_to) uses sampled coordinates. stat.interp_ij(values_ij, i_to, j_to) replaces both selected axis extents; interp_...i preserves anonymous dimensions outside the selected axis. Interpolation is numerical, not a second symbolic interpolation API.

UI, colors, and units

The UI accepts generic axes in colormaps such as jet_i and two-axis alpha/color maps such as alpha_jet_ij. .ui.colormaps contains standard palette families and their alpha variants. The first alpha selector controls opacity; the second controls color. Extra real axes group output unless a selector consumes them. Position components use p, color components use c, and complex coordinates must be converted explicitly before plotting. Coordinate limits and modes govern colormap normalization. Omitted plot color uses the contrasting viridis endpoint for the active theme. Numeric c values use viridis by default; explicit colors and colormaps remain authoritative.

Coordinate channels use ordinary named-axis broadcasting; they do not need the same raw shape. For example, x_u aligns with y_ui on _u and broadcasts across _i. Only different extents on the same named axis are incompatible.

Viewport.add accepts the complete output-data vocabulary x, y, z, p, v, a, t, c, text, r, phi, and theta. Every palette and reversed palette also provides whole-name _phi and _theta selectors for angular color data.

UI argument names are channels, not values: write viewport.add(x:x_i,y:y_i, cmap:viridis_y). The compiler rejects indexed argument names such as x_i: and rejects the removed color_by: and colormap: controls. Unindexed containers remain valid and receive an implicit grouping index; explicit value indices are recommended. _i and _t establish those dimensions directly; separate i: and t: coordinate values are optional.

.ui.viewport is the root plotting surface and is bound directly rather than constructed. It exposes add, push, add_window, and add_panel; Window and Panel also expose add and push. Desktop compilers lower the root to the transparent overlay host; browser WebAssembly hands the host embeddable <vkf-viewport>, <vkf-window>, and <vkf-panel> elements. A Window has a movable, resizable title bar; a Panel has no handle or border. Relative pos, width, and height fields may vary over ordinary indices, and later add calls with the same suffix axes join those surfaces by supplied coordinate value or, when omitted, by position. A View is a stacked plot composition: view_title:titles_k creates the stack and matching _k data routes into it. Each View exposes the merged coordinates of every routed layer to its picker.

Window and Panel toolbars may sit on any edge. They own navigation, View selection, picking, still capture, video capture, and—only for animated Views—play/pause, reset, and playback rate. Direct time control uses a separate range Input and SliderValueChanged => view.t:event.value; that one t value selects every _t channel in the View. HTML controls remain styleable with ordinary CSS. Colorbars are deferred.

The SI catalog is imported explicitly with :.units.si. Unit spellings keep case significant and prefixed units resolve by exact name or longest valid prefix. Numerical domains, physical dimensions, units, and angle semantics remain separate concepts. Native and browser output preserve the left operand's preferred unit for compatible scalar addition: :: 2m + 30cm prints 2.3 m, while :: 30cm + 2m prints 230 cm. A vector carries one unit for the whole value: :: [1,2,3]m prints [1, 2, 3] m. These are compile-time type and output-formatting changes; runtime arithmetic stays in canonical SI. Explicit conversion changes preferred representation without changing the stored magnitude: (2m).to(cm) prints 200 cm, and ([1,2,3]m).to(cm) prints [100, 200, 300] cm. The compiler rejects incompatible dimensions. Configurable display units, automatic SI prefix selection, and angle-kind handling are not yet release-ready.

Commands and concurrent events

.command is for serial operating-system commands. .concurrent.process starts an ordinary VKF worker; queue, broadcast, and shared values describe event/I/O coordination. Ordinary numerical parallelization remains a Quantum compiler decision. These are distinct APIs; process does not stand for a shell command. The public shared-generation update surface remains unresolved.

Published targets and verification

0.4.7 publishes native compiler packages for Windows x64 and Linux x64, plus the browser WebAssembly compiler. Each packaging lane builds from the tagged source and must pass its native or browser correctness suite before the GitHub release is created. The native lanes exercise ordinary worker argument binding, isolated process, result-returning join, forced kill, blocking FIFO queue, subscriber fan-out broadcast, and shared bulk values across execution contexts.

This release intentionally omits the macOS compiler. Local 100-run receipts compare four of the five established native workloads with C++, Rust, and Zig on Windows x64 and Linux x64. A separate Windows receipt compares Firefox WebAssembly across VKF, C++, Rust, and Zig and against same-host native VKF. The combined-parallel workload did not compile in the benchmark harness, and macOS, Chrome, Safari, linear-algebra, and symbolic comparisons were not run; their table cells are — rather than being filled with results from another version. These measurements are scoped to their tagged source, host, toolchain, and sampling policy.

CUDA/WebGPU device planning for suffix-aware contractions is a later optimization phase. The current release does not establish automatic GPU acceleration for large matrix products.

Vektor Flow remains unsupported experimental software with unstable APIs and syntax.
