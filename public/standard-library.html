VKF Standard Library

The standard library is separate from VKF syntax. This page describes each published library, how to bring it into scope, what it is useful for, and a runnable example. The syntax reference explains the language constructs used by those examples.

Importing and using a library

A dotted name on the right of a declaration creates a module handle, as in math: .math; calls then remain qualified as math.sqrt(...). A leading colon spills public names into the current scope, as in :.linalg; functions such as dot(...) can then be called directly. Nested modules use the same forms, including :.physics.units.

Qualified imports make dependencies obvious and are the default in the examples below. Spilling is useful for mathematical libraries where repeated qualification would obscure a formula. The SI catalog is :.units.si; it is not imported by :.physics. Each editor starts with the relevant import and can be compiled in the browser when that library has a browser-safe implementation. Native-only capabilities are labelled explicitly.

2. stat

Functions include sum, mean, count, min, max, range, variance, std, percentile, median, iqr, mode, zscore, normalize, covariance, correlation, clamp, and sign. sum reduces every nested vector dimension by default. A selected reduction can use a compile-time structural suffix, stat.sum_j(values_ij), or an ordinary runtime axis argument, stat.sum(values, 1). The suffix is preferred when the axis is statically known because it exposes the structural fact to the compiler.

Every structural statistic has the corresponding runtime-axis form. The axis is the final positional argument after data parameters: stat.median(values, axis), stat.percentile(values, p, axis), and stat.covariance(x, y, axis). Runtime axes use the same grouping and result-shape rules as their suffix forms; they simply do not carry the source label into optimization metadata.

For a matrix, stat.sum_i reduces the i dimension and returns column sums; stat.sum_j reduces the j dimension and returns row sums. The equivalent runtime form is stat.sum(values, axis); for example, stat.min(matrix, 1) reduces each row. Compile-time reduction currently requires a fixed rectangular numeric vector. Duplicate and unknown suffix dimensions are compile errors. variance and std accept ddof; zero is the population form and one is the sample form.

For compile-time dimensions, the result keeps every non-reduced dimension:

For example, stat.sum_i(matrix_ij) produces the remaining j values, while stat.sum_j(matrix_ij) produces the remaining i values. An index-space stride is written stat.sum_i(values_i, i_step:2). With sampled values and a coordinate vector, stat.sum_x(samples_x, x:x, x_from:0, x_to:2, x_step:0.5) interpolates at the coordinate lattice 0, .5, 1, ... before reducing.

All controls are governed by the selected suffix axis: stat.sum_q accepts q:, q_from, q_to, and q_step; integ_q uses dq as its constant measure. Without a coordinate vector, a sum step is a non-zero integer index stride. With q: it is a coordinate-space step and the sampled values are linearly interpolated at the resulting lattice. A reversed sum whose step has the wrong direction is empty and therefore returns 0; symbolic expressions use the same public stat.sum_q surface.

stat.interp_i(values_i, i_to) is numerical interpolation over index coordinates. Supplying i explicitly uses sampled coordinates: stat.interp_i(values_i, i, i_to). Multiple selectors and target vectors replace their corresponding extents, as in interp_ij(values_ij, i_to, j_to); interp_...i preserves anonymous dimensions outside the selected axis.

4. time


wall_time, monotonic, sleep, time_stamp, format_time, and current_time are native. Formatting accepts UTC selection and percent directives.


Browser execution supplies wall_time and monotonic through one versioned ClockArena sample per Play, tick, or event. It has no ambient host-call access. Filesystem I/O, operating-system inspection, and native process launch remain browser-forbidden and receive explicit compiler diagnostics.

5. io


print, eprint, read_line, read_text, read_bytes, write_text, write_bytes, and append_text perform native stream and file I/O.

Native file operations use the current user's permissions and paths are not sandboxed. Browser read_text, write_text, and append_text instead use a session-scoped RAM DocumentArena. Browser paths must be normalized relative paths using /; the arena allows 64 documents, 8,192 UTF-8 bytes per document, and 49,152 live bytes total. It is cleared on refresh or reset and never grants filesystem, persistent-storage, network, DOM, or download capability.

10. .concurrent


.concurrent is the event and I/O concurrency library.  It is deliberately separate from Quantum: numerical vectorization, CPU/GPU placement and kernel fusion remain compiler-managed and do not require processes or explicit threads.


concurrent: .concurrent

events: concurrent.queue()
updates: concurrent.broadcast()
state: concurrent.shared((mode:"run", samples:[1,2,3]))

worker(events, state):
    (event:events.get())??>
        Stop => state
        worker(events, state)

p: concurrent.process(worker, events, state)
events.put(Stop)
:: p.join()


process(...) starts an ordinary VKF function in an isolated execution context.  Its arguments use ordinary VKF call binding and spilling; there is no concurrency-specific packing syntax.  p.join() waits and returns the worker result.  p.kill() is forced termination; normal termination is message/program driven.


queue() is a destructive FIFO: put(value) sends one value and get() suspends efficiently until one exists.  If several receivers wait, a queued value is delivered to exactly one receiver.


broadcast() permits many producers and subscribers.  Each updates.subscribe() returns a queue-like branch.  Every active subscriber receives every value published after subscribing; ordering from a given producer is preserved.


shared(value) takes exactly one arbitrary VKF value. It preserves normal value structure while providing compiler/runtime-selected shared backing. It does not expose mutable pointers: readers observe immutable published generations. Send small descriptors through queues and keep bulk numeric state shared rather than copying it through messages. The public API for publishing or rebinding a later generation is intentionally not specified yet.


The complete native examples separate the two communication shapes: event_pipeline.vkf uses a destructive work queue, a process and shared bulk state; and fanout.vkf gives a UI and logger their own broadcast subscriptions. They are intentionally ordinary VKF programs, not a second parallel-loop language.


The browser target resolves .concurrent but rejects reachable concurrency operations until its isolated-worker runtime is present; it never silently lowers them to host access.

12. linalg


:.linalg uses ordinary rectangular nested vectors rather than a separate matrix class. Numeric operations include dot, cross, outer, matmul, transpose, trace, determinant, rank, inverse, solve, least_squares, solution_space, rref, null_space, lu, qr, cholesky, svd, and eigen.

13. physics And Dimensioned Units


Import the engine and units separately. :.units.si spills the SI catalog; unit symbols are not spilled by :.physics.

Both 2km and 2 km are quantity literals. A unit supplies its scale and one seven-exponent physical dimension. Multiplication and division add and subtract dimensions; addition, subtraction, ordering, and equality require matching dimensions. The native SI catalog provides all seven bases, coherent derived units, and prefixes from quecto through quetta. SI is the only catalog currently declared; future catalogs may change names and scales but never the dimension model.


The engine surface includes 2D/3D vectors, 3×3 matrices, tetrahedral mass properties, rigid momentum stepping, collision matrices, restitution, tangential/rolling/spin friction, coupled solid contacts, materials, and the deterministic dice example. Rigid-body functions live only in physics; there is no release rigid_body compatibility module.


14. symbolic


:.symbolic provides domains N, Z, Q, R, and C; exact expression construction; elementary functions; expansion and collection; simplification; substitution; evaluation; differentiation; integration; and truncated series multiplication.


The public hierarchy is Expression, with Symbol IS Expression, Constant IS Symbol, and Relation IS Proposition IS Expression. Symbolic = and the ordered comparison operators create relations. => has lower precedence than those operators and joins propositions without parentheses. It preserves a symbolic Proposition; with two bit operands it evaluates ordinary logical implication. The same token remains the arm separator after ??, where its role is fixed by the match context.

In symbolic code, an unbound adjacent name such as xy is decomposed only when it has one unambiguous factorization into already-bound symbolic names. A real xy binding wins. Consequently 1/xy above is 1/(x*y), while the space in 1/x y resumes the outer product and gives (1/x)*y. Ambiguous factorizations are compile errors; * or parentheses always make intent explicit.


Literal adjacency uses the same multiplication rule for values and symbols: a:3; 3a+4^2 evaluates to 25, while x:R; 3x+4^2 constructs an evaluable Expression. Symbol spelling is case-preserving. Ordinary multi-character names render with \operatorname{...}; a one-character subscript stays exact (x_r renders as x_{r}), while a multi-character subscript uses \mathrm{...} (x_tot renders as x_{\mathrm{tot}}).

15. ui


.ui.viewport is the retained root surface for interactive 2D and 3D views; bind it directly with viewport: .ui.viewport. Each viewport.add call contributes one layer. Plot directly on it, or bind a window:(...) or panel:(...) struct to split data into child surfaces. A Window has a title bar and desktop controls. A Panel has no border or handle. Coordinate arguments name only the visual channel. Structural indices stay on their values: x:x_i supplies independent x coordinates, x:x_u supplies one connected path, and x:x_iu supplies a family of paths. Indexed argument names such as x_i: are invalid. An unindexed container is valid and receives an implicit grouping index; explicit value indices are preferred because they name every dimension. The suffix order is the nesting order, so the outer rows of x_iu are the independent i groups and each inner row follows the connected u axis. Positional p maps component values to x, y, and z. An explicit p may appear in its own suffix (p_up, p_tpu); that axis is removed after its extent selects two or three spatial components, while all other axes keep their authored order. Without a component p, as in p_tiu, each leaf may instead be a two- or three-component position value.


Color follows the same rule. In c_ic or c_tc, the suffix c is the RGB or RGBA component axis and may appear anywhere; alpha is always the optional final component and defaults to 1. Numeric color components are normalized values from 0 to 1—not 0 to 255. Uniform and distributed colors may also use names or hex strings, for example color:"red" or c:["red","#00ff0080"]_i. When color is omitted, the active theme selects the contrasting endpoint of viridis. Numeric c data without an explicit cmap is normalized through viridis. Explicit color, RGB/RGBA c, and cmap values disable these defaults.


The complete output-data vocabulary is x, y, z, p, v, a, t, c, text, r, phi, and theta. Indices still belong to values, so write phi:angles_u, not phi_u:angles. Unindexed values remain valid groups. Every supplied value establishes its own indices. Separate coordinate data such as i:is or t:ts is optional; _i or _t already identifies that dimension.


Colormaps use suffix selectors from .ui.colormaps: cmap:viridis_y means that y is the normalized color coordinate, and cmap:alpha_jet_iy uses i for alpha and y for jet. Every standard palette is available, including the perceptual, sequential, diverging, cyclic, categorical, and legacy scientific families; _r reverses any palette. One-character numeric channels use their ordinary suffix. The two longer channels have whole-name selectors on every palette, for example viridis_phi and viridis_theta; they read the matching phi: or theta: data instead of splitting the name into axes. The selected coordinate's own y_lim/y_min+y_max controls normalization, while y_mode selects extend, clamp, repeat, mirror, or discard outside that range.


An additional real structural axis is ordinary layer grouping unless a cmap selector consumes it. Plotting never silently vectorizes coordinate output. Coordinate output must be real: express complex-derived channels explicitly, for example [abs(p),arg(p)]_qic.


The examples below are deliberately different programs rather than one option split into many near-duplicates. Their data is generated from ranges: i and u examples use at least 41 and usually 101 values, uv uses a 41 by 21 grid, and animation uses 101 authored t samples. add owns layer data and material; push owns limits and labels; show makes the viewport visible. Edit any example and press Run.


On desktop, the compiler lowers the root Viewport to the native transparent overlay host; a Window adds its movable title bar and controls. In a browser, the WASM result becomes embeddable <vkf-viewport>, <vkf-window>, and <vkf-panel> HTML elements. Layout is relative to the parent viewport: pos:[0,0] is its top-left and width or height 1 spans it. Structured and flattened fields are equivalent, such as panel:(pos:[0,0],width:0.5) and panel_pos:[0,0],panel_width:0.5. Bind the struct itself to axes— window:(width:0.5,height:0.5)_ij—then matching _ij data is partitioned over those windows. Later add calls carrying _ij join the same windows. Matching uses supplied i: and j: coordinate values when present and index positions otherwise. title supplies the Window title bar text. A Window or Panel may add a toolbar on any edge with toolbar:"top", "right", "bottom", or "left"; omitting it leaves the surface clear. The toolbar owns Home, Back, Forward, zoom, View selection, coordinate picking, still capture, and video capture. Animated Views additionally show Play/Pause, Reset, and playback rate; static Views hide those controls. Direct time control uses a separate range Input: retain the View returned by push, then write SliderValueChanged => view.t:event.value. The compiler maps that t value through every _t channel in the View. The toolbar never owns a time slider. The control remains ordinary HTML, so normal style sheets own its appearance. Within a Window or Panel, view_title:titles_k creates a stack of named Views; later _k data follows the same value-or-position matching rule. A View is a stacked plot composition, not another surface, and the host supplies the control for switching Views. Each View exposes the union of coordinates contributed by every routed add. Its picker shows explicit coordinate values when supplied and ordinal coordinates otherwise, for Cartesian, polar, time, color, and arbitrary grouping axes.


Regular coordinates below use generated ranges rather than long literal data lists. One-dimensional curves use at least 401 points for smooth display; multidimensional grids remain smaller where their product would be costly.


Viewport, Window, and Panel each expose add and push. add contributes data to the current View; push seals that composition and returns its View handle. Viewport also exposes add_window and add_panel for child surfaces.
